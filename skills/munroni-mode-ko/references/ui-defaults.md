# 화면 기본값

새 화면, 시안, 폼을 만들 때 처음부터 넣는다. 사용자가 다시 짚게 만들지 않는다.

## 단순하게, 그러나 구조는 보이게

- 장식을 넣지 않는다: 왼쪽 강조 세로줄, 타임라인 연결선과 동그라미, 이니셜 동그라미, ⓘ 아이콘과 회색 안내 상자, 상태나 메뉴 줄 앞의 색 점, 지표 칸 세로 구분선, 같은 값 반복, 장식용 그라데이션. 범례가 필요하면 실제 그림(지도 핀 등)을 쓴다. 끝난 단계에 붙이는 체크 표시(원 없이)는 장식이 아니다.
- 중복 표시, 필요 없는 숫자와 단계 번호, 상시 안내 문구("~만 볼 수 있습니다", "테스트입니다")를 넣지 않는다. 권한은 설명하지 않고 안 보이게 한다. 남기는 문구는 오류, 되돌릴 수 없는 동작의 확인 문구, 파일 개수와 용량 같은 수치 제약뿐이다.
- 무언가를 빼면 그 자리 빈 공간도 없앤다. 화면 위쪽은 가볍게 둔다.
- 단순함은 구조가 안 보인다는 뜻이 아니다. 묶음이 여럿이면 면색 머리 띠나 테두리 패널 같은 구조 요소로 경계를 드러낸다. 1초 안에 묶음 개수가 세지는지로 점검한다.
- 색은 적게 쓴다. 포인트 색은 브랜드 기본색 하나다. 상태 구분도 이미 있는 색을 다시 쓴다. 표 머리글과 제목 글자는 칠하지 않는다. 제목과 합계 금액을 크게 키워 위계를 만들지 않는다. 위계는 간격, 글자색, 굵기로 잡는다.
- 선택된 줄은 흐린 화면에서도 보이게 면색에 테두리를 더한다.
- 새 기능마다 탭이나 메뉴를 늘리지 않는다. 그 데이터가 이미 있는 화면에 붙이고, 폼은 작은 창으로 연다.
- 외부 사용자(고객, 거래처) 화면은 내부 화면보다 단순하게 만든다. 교육 없이 "지금 내가 할 일"이 보여야 하고, 그 순간 누를 버튼은 하나다. 내부 상태가 몇 개든 할 일 묶음 몇 개로 보인다. 내부 분류 이름과 내부 금액(수수료, 마진 등)은 보이지 않는다.

## 표

- 헤더는 늘 가운데 정렬이다. 본문은 제목, 메모 같은 문장만 왼쪽이고, 나머지(상태, 번호, 담당, 날짜, 금액, 수량)는 가운데다.
- 금액은 단위까지 쓴다(15,000원). 숫자와 글자가 섞인 칸은 둘로 나눈다. 좁은 화면 카드에서는 표 정렬을 풀고 왼쪽에 붙인다.
- 조회 조건은 위쪽 필터 줄에 둔다. 표 보기 컨트롤(보기 전환, 접기, 엑셀)은 표 바로 위 오른쪽에 둔다. 둘을 섞지 않는다.

## 컨트롤 모양과 이름

- 종류는 모양으로 구분한다. 켜고 끄기는 스위치, 동작은 버튼, 둥근 칩은 하나만 고르는 필터에만 쓴다.
- 같은 동작은 같은 모양과 같은 이름이다. 줄 위치에 따라 색을 바꾸지 않는다. 화면만 여는 버튼에 실행을 뜻하는 이름("보내기")을 붙이지 않는다.
- 동작 버튼은 아이콘과 글자를 같이 쓴다. 아이콘만 쓰는 것은 보편적이고 안전하며 좁은 자리(닫기, 새로고침, 엑셀 받기)뿐이고, 그때 aria-label과 title을 둘 다 단다. 조회, 취소, 적용은 글자만 쓴다. 삭제, 발송, 결제 같은 위험한 동작은 글자를 꼭 남긴다. 줄 안의 "열어 보기"는 상자 버튼 대신 색 글자와 작은 아이콘으로 쓴다.
- 업무 화면 라벨은 그 업무에서 이미 쓰는 용어로 쓴다(예: 주문, 청구, 대기). 풀어 쓴 구어체("만들 것", "답 기다림")는 쓰지 않는다. 라벨은 보는 사람 입장의 이름으로 쓴다.

## 색의 뜻

- 빨강은 삭제와 정해진 날짜를 넘긴 것에만 쓴다. 삭제 확인 버튼은 빨강 채움, 줄 안의 삭제 글자와 휴지통도 빨강이다. 빨강 값은 하나로 통일한다. 닫기, 빼기, 취소의 ×는 빨강이 아니다.
- "지연"은 정해진 기한이나 납기를 넘긴 것에만 쓴다. 들어온 뒤 지난 날수에는 지연, 빨강, 주황을 쓰지 않고 "N일 전" 글자만 쓴다. 오래된 건을 드러내려면 오래된 순 정렬을 쓴다.

## 창과 확인

- 입력 칸이 있는 창은 바깥을 눌러도 닫히지 않는다. [취소]와 Esc로만 닫는다. 확인 창, 보기 창, 팝오버는 바깥을 누르면 닫힌다.
- 상대(고객, 거래처, 다른 부서)의 상태를 바꾸는 버튼은 "무엇이 어떻게 됩니다. 할까요?" 확인 창을 띄운다. 문구에 실제 값(상대 이름, 금액)을 넣는다. 사유를 입력하거나 고르는 창은 그 자체가 확인이라 확인 창을 겹치지 않는다. 메모, 파일 추가, 임시 저장은 확인 없이 실행한다.
- 동의 체크는 확정 버튼 바로 위에 둔다. 글자는 결과를 말하는 사실 한 줄로 쓴다. 예: "결제 후에는 주문을 취소할 수 없습니다". "~에 동의합니다" 말투는 쓰지 않는다. 오류 문구는 "위 내용을 확인하고 체크해 주세요."다.
- 읽기 전용 긴 글은 팝업으로 띄우지 않고 그 자리에서 펼친다("전체 보기", "접기"). 긴 묶음은 접어 두고, 목록에서 골라 들어가면 고른 것만 펼친다.
- 실패는 보이게 한다. 발송 실패나 반송을 "완료"로 두지 않고 알림을 띄운다.

## 입력

- 입력 편의는 시키기 전에 넣는다: 전화번호와 사업자번호 자동 하이픈, 금액과 수량 쉼표(커서 위치 유지), 숫자 칸 숫자 키패드(inputMode), 주소 검색, 이름·회사·주소 자동완성, 이메일 칸 type="email". 저장은 숫자만 하고 화면에는 서식을 붙여 보인다.
- 숫자 칸에 남는 0을 보이지 않는다. 다시 열면 저장한 값으로 열고 기본값으로 덮지 않는다. 적용된 설정(예: 몇 %)은 볼 때 보인다. 여러 줄 글은 줄바꿈을 살린다.
- "직접 입력"은 고르는 칸 안에서 바로 쓰는 콤보박스로 만든다. 아래에 칸을 하나 더 만들지 않는다.

## AI 표시

- AI를 부르는 동안 회전 표시와 "AI가 읽는 중…" 글자를 보이고, 버튼을 두 번 못 누르게 한다. 회전 표시는 공용 부품 하나로 쓴다.
- AI가 만든 기록과 초안에는 작게 "AI 작성"만 붙인다. 고객에게 나가는 문서에는 붙이지 않는다.
- 자동화는 분류와 초안까지만 한다. 바깥 발송과 확정은 사람이 버튼으로 한다. 사람에게 넘기는 "확인 필요" 건수는 최소로 줄인다.

## 폰과 마감

- 폰 목록의 필터는 위에 늘어놓지 않는다. 지금 조건 한 줄과 "필터 n" 버튼을 두고, 누르면 아래에서 시트가 올라온다.
- 작은 화면에서는 전체 크기를 줄여 한눈에 보이게 한다. 글자와 줄 높이를 키우지 않는다.
- 보고 전에 마감을 확인한다: 가운데 정렬, 그림자 크기, 테두리 흰 띠, 잘림(로고 등), 칸 밖으로 나간 아이콘, 어색한 공백과 겹침.
- 새 섹션을 넣은 뒤 주변 기존 배치(열 수, 좌우 교차)가 그대로인지 확인한다. 요청 없이 기존 배치를 바꾸지 않는다.
